# Unit-test coverage

## Targets

NFR-8 (see [`product.md`](./product.md)) requires unit tests for markdown round-trip, annotation serialize/deserialize, share codec, and diff computation. The coverage gate fails the build when any of these metrics drops below **90%**:

| Metric     | Threshold | Today  |
| ---------- | --------- | ------ |
| Lines      | 90%       | 99.57% |
| Statements | 90%       | 98.05% |
| Branches   | 90%       | 91.82% |
| Functions  | 90%       | 98.43% |

The "Today" column is a snapshot from the initial wiring; it ratchets up naturally as tests are added but the floor stays at 90 until the threshold is bumped intentionally.

## Scope

Coverage is measured on the NFR-8 surfaces only — the modules the spec names by hand:

- `packages/symbiot-annotations/src/**/*.ts` — markdown round-trip, annotation serialize/deserialize, share codec.
- `packages/symbiot-editor/src/utils/**/*.ts` — diff computation and annotation-mark utilities.

Out of scope and excluded explicitly:

- `packages/symbiot-editor/src/utils/{shiki,sourceLines,typingGuard,selectionRect}.ts` — adjacent utilities not named by NFR-8 (syntax highlighting, source-line resolution, type guards, UI selection geometry).
- All React component code in `packages/symbiot-editor/src/components/**` and `packages/symbiot-ui/**` — composition gating is tracked separately in [#123](https://github.com/awinogradov/symbiot/issues/123).
- `apps/**` — coverage on app code lives behind the e2e flow (`bun run test:e2e:coverage` + `mcr.config.ts`), not this gate.

## Running locally

```sh
bun run coverage
```

Runs `vitest run --coverage` with the v8 provider. The HTML report lands at `coverage/index.html` — open it in a browser to drill into per-file metrics. The `coverage/` directory is git-ignored.

When the gate fails, vitest exits non-zero and prints the failing metric(s); the report is still written so the gap is inspectable.

## PR comment

Every PR run posts a sticky comment via [`davelosert/vitest-coverage-report-action@v2`](https://github.com/davelosert/vitest-coverage-report-action). The comment shows the summary table plus per-file deltas against `main` and updates in place on each push. The comment posts even when the threshold gate fails (`if: always()`) so reviewers see the number without chasing artifacts.

The action reads `coverage/coverage-summary.json` and `coverage/coverage-final.json`, which `bun run coverage` produces via the `json-summary` and `json` reporters configured in `vitest.config.ts`.

## Updating thresholds

The thresholds in `vitest.config.ts` are deliberately a floor, not a ceiling. Coverage will exceed them in normal operation.

- **Raising** — once a metric has comfortably sat above the next round number for a few PRs, bump the threshold in `vitest.config.ts`. No external bookkeeping needed.
- **Lowering** — never lower without an explicit reason. If a refactor temporarily drops coverage, fix the tests; do not weaken the gate. The only legitimate use is a major reorganisation where lowering is paired with a tracking issue to ratchet back up.

## Relation to e2e coverage

E2E coverage is generated by Playwright + `monocart-coverage-reports` and lives under `coverage/e2e/`. It measures app code (`apps/viewer/src/{client,server,shared}/**`) under real browser interactions, scoped via `mcr.config.ts:sourceFilter`. The two reports do not overlap and are not summed.
