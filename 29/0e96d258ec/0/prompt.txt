**How the server knows review is "done" (critical for #172):** There is **no polling and no long-poll**. `startServer` creates a single `resolved` Promise (`startServer.ts:126-129`) and passes `resolve` into every request's `ctx`. The approve/deny/feedback handlers call `finalize(ctx, decision)` (lines 181-188), which: (1) `clearDraft`, (2) `ctx.markResolved()` (flips `resolvedFlag` so late `POST /api/draft` becomes a 204 no-op — line 215), (3) optionally writes `decisionFile` JSON `{...decision, at:Date.now()}` for out-of-band readers (Playwright), (4) `ctx.resolve(decision)`. The agent/runtime side (`runPlanReview.ts:70`) simply does `await server.resolved` then `server.stop()`. So the "wait" is an in-process Promise resolved by an HTTP POST — a **one-shot** lifecycle: one decision ends the server.

For an iterate-until-approve `draft` flow you'll need to either loop `startServer` per revision, or change this one-shot model (e.g. a decision kind that persists a new version + keeps the server alive instead of resolving). `savePlan` (bumps version) is currently only called once at boot in `initStorage`.

### 3. Hook flow — `apps/claude-code/src/runHook.ts` + `hooks/hooks.json`
`hooks.json` registers three hooks, all calling `"${CLAUDE_PLUGIN_ROOT}/bin/symbiot"`:
- `SessionStart` → `prepare` (timeout 120)
- `PreToolUse` matcher `ExitPlanMode` → `run-hook` (timeout 3600)
- `PermissionRequest` matcher `ExitPlanMode` → `run-hook` (timeout 3600)

`runHook()` reads JSON from stdin (`HookInput { hook_event_name, tool_name, tool_input:{plan} }`), logs to `~/.symbiot/hook-state/events.log`, extracts plan only when `tool_name === "ExitPlanMode"`. Then branches:
- **PreToolUse** (`runPreToolUse`): `runPlanReview({ plan, serverOptions:{indexHtmlGz, agentId:"claude-code"}, onStart, onResolved })`. On `decision.kind === "approve"` → `writeApproveMarker(sha256(plan))` to `~/.symbiot/hook-state/last-approve.json` (atomic tmp+rename), then emits `permissionDecision:"allow"` PreToolUse payload (currently a no-op vs upstream bug #50660). Otherwise → `emitBlockDecision(decision.feedback)` (the `{"decision":"block","reason"}` shape). Always returns 0.
- **PermissionRequest** (`runPermissionRequest`): reads the marker, checks `isFreshFor(marker, sha256(plan), now)` (hash match + `&lt; 60_000ms`); if fresh emits the nested allow payload `{hookSpecificOutput:{hookEventName:"PermissionRequest", decision:{behavior:"allow", updatedPermissions:[{type:"setMode",mode:"acceptEdits",destination:"session"}]}}}`; else writes nothing (falls through to native prompt).

Decision JSON shapes: approve = `permissionDecision` allow (PreToolUse) / nested `decision.behavior:"allow"` (PermissionRequest); deny/request-changes = `{"decision":"block","reason":&lt;feedback&gt;}`. Exported helpers: `markerPath`, `hashPlan` (= `sha256`), `writeApproveMarker`, `readApproveMarker`, `isFreshFor`, `permissionRequestAllowPayload`, `approveMarkerTtlMs`.
